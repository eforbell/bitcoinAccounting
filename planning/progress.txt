## Codebase Patterns
- Whitespace normalization: LedgerWriter.strip() on exchange param at top of each method; guard None with isinstance check in import_transactions
- Wallet selector pattern: Use `_mount_wallet_selector(container, label, select_id)` shared helper; IDs from `_WALLET_SELECT_MAP`; `_get_exchange_value(select_id)` reads from Select or Input
- Textual Select._options: Stored as list of (prompt, value) tuples, not objects with .value attribute
- Textual remove_children() is async: IDs not deregistered immediately; use `_sync_clear_children()` when mounting new widgets with same IDs in same handler
- Import Wizard wallet selector: Use `_mount_wizard_wallet_selector()` with `_WIZARD_WALLET_MAP`; `_get_wizard_wallet_value(select_id)` reads effective value; display toggled via `new_row.display` (not CSS classes)
- Textual CSS class gotcha: CSS `.new-wallet-row { display: none }` overrides `widget.display = True` set programmatically; use `display` property without conflicting CSS rules
- Duplicate detection in Import Wizard: Call `detect_duplicates(transactions, app.crypto.backend)` in `show_step_3()`; store results in instance var; show warning banner with Static widget; mark duplicates with ⚠ prefix
- CLI input validation: Use `prompt_float()/prompt_int()` helpers with try/except around conversions; re-prompt on ValueError; strip() all wallet/exchange name inputs
- ModalScreen pattern: Use `ModalScreen[ReturnType]` with centered Container; form with Label + Input/Select rows; Button row with primary/default variants; handle dismissal callback in parent screen
- Edit modal pattern: Pass data via `__init__(data: dict)`, pre-populate form fields, use read-only Label for immutable fields, build updates dict with only changed values
- **CRITICAL: All write operations must call `backend.commit()`** - SQLite does NOT auto-commit by default; without explicit commit(), changes stay in memory and are lost
- Rename modal pattern: Show transaction count warning, require typing new name twice for confirmation, validate not empty/same/duplicate
- Soft-delete filter pattern: All ledger SELECT queries must include `AND (deleted = 0 OR deleted IS NULL)` to exclude soft-deleted rows; NULL check handles pre-migration rows
- Schema migration pattern: Use PRAGMA table_info() to check existing columns before ALTER TABLE ADD COLUMN (SQLite lacks IF NOT EXISTS for columns); run migration in create_tables()
- TransactionQuery includes ID and Deleted columns: `get_transactions()` returns `l.id "ID"` and `l.deleted "Deleted"` for use by edit/delete modals
- LedgerWriter CRUD pattern: `_get_transaction(tx_id)` validates existence and returns row dict; `UPDATABLE_FIELDS` frozenset whitelists allowed update columns; `update_transaction(tx_id, **kwargs)` filters kwargs against whitelist, strips exchange, builds dynamic SET clause with quoted "group" column
- TransactionDetailModal pattern: `ModalScreen[str | None]` returning action ("edit"/"delete"/None); receives tx dict via `__init__`; `_DETAIL_FIELDS` list of (label, key) tuples drives compose(); `on_data_table_row_selected` in parent uses `filtered_transactions[cursor_row]` to get tx data
- Textual Label content access: Use `label.content` (str), NOT `label.renderable` (doesn't exist in this version)
- Textual on_mount vs compose() children: When widgets are mounted via `container.mount(widget)`, compose() children may not be queryable in `on_mount`. Use `set_timer(0.05, callback)` with try/except guard to defer.

### Textual Widget Mounting Patterns (CRITICAL)
- **Mount parent before children**: Always mount container to its parent BEFORE mounting children to container
  - BAD: `row = Horizontal(); row.mount(widget); container.mount(row)` ❌ (Can't mount to unmounted parent)
  - GOOD: `row = Horizontal(); container.mount(row); row.mount(widget)` ✅
- **Mount before querying**: Mount widget BEFORE calling methods that query for child elements
  - BAD: `widget.update_data(); container.mount(widget)` ❌ (Widget not mounted, can't query children)
  - GOOD: `container.mount(widget); widget.update_data()` ✅
- **Constructor + on_mount pattern**: Pass data to constructors, call update methods in on_mount()
  - Pattern: `__init__(self, data) -> store data; on_mount(self) -> self.update_with_stored_data()`
  - This ensures widget is fully mounted before querying children
- **Avoid TabbedContent dynamic mounting**: TabbedContent manages internal tab registry, manual TabPane mounting breaks it
  - Prefer: Simple Container hierarchy or proper compose() patterns
  - If using tabs: Use compose() to yield TabbedContent with TabPane children, don't mount manually

### Textual Layout & Styling Patterns
- **Flexible height**: Use `height: auto` with `min-height` for content that varies
  - Add `max-height` to prevent excessive expansion (e.g., `max-height: 15` for tables)
- **Explicit layout**: Add `layout: vertical` to containers that stack children vertically
- **Fractional widths**: Use `width: 1fr` to distribute space equally among siblings
- **Terminal compatibility**: Avoid Unicode box-drawing chars (█▓▒░), use Rich markup colors instead
  - Good: `[green]Self-custodied: 45.2%[/green]` ✅
  - Bad: `██████████▓▓▓▓▓▓▒▒▒░░` ❌ (renders poorly in some terminals)

### Database Cross-compatibility Patterns
- **SQLite threading**: Set `check_same_thread=False` for TUI @work(thread=True) workers
  - Safe for read-heavy workloads with single writer
- **Boolean queries**: Use `TRUE`/`FALSE` keywords (work in both SQLite and PostgreSQL)
  - BAD: `WHERE active = 1` ❌ (PostgreSQL: "operator does not exist: boolean = integer")
  - GOOD: `WHERE active = TRUE` ✅ (works in both databases)

### Textual Navigation Patterns
- **Screen binding for back**: Use `Binding("escape", "app.pop_screen", "Back", show=True)` on screens
- **Button focus**: Textual buttons are focusable by default, Tab cycles through them automatically
- **Discovery UX**: Show keyboard shortcuts in button labels: `Button("Portfolio [P]", ...)`

### Textual TabbedContent Patterns
- **Compose with TabPane children**: Yield TabbedContent with TabPane children inside compose()
- **Tab switching**: Use `tabbed.active = "tab-id"` to switch tabs programmatically
- **Tab visibility**: Each TabPane needs unique id for switching: `TabPane("Label", id="tab-name")`
- **Testing tabs**: Call screen methods directly instead of pilot.click() (buttons may be off-screen)
- **Container visibility**: Use `container.display = True/False` for dynamic show/hide sections
