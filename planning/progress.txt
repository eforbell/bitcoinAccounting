## Codebase Patterns

- **Named Placeholders**: Both sqlite3 and psycopg2 support `:named` syntax with dict parameters. Use this for cross-database compatibility instead of `%s` or `?`.
- **Python 3.9 Type Hints**: Add `from __future__ import annotations` to use `|` union syntax on Python 3.9.
- **Optional Dependencies with mypy**: Use `TYPE_CHECKING` pattern to conditionally import types without runtime failures.
- **SQLite Row Factory**: Set `connection.row_factory = sqlite3.Row` to enable `dict(row)` conversion.

  - `tests/test_db_backend.py` (modified - added TestPriceLookup class with 10 tests)
  - `AGENTS.md` (updated)

- **Learnings:**
  - Date/time functions are fundamentally incompatible between SQLite and PostgreSQL - must generate separate SQL per backend.
  - Backend type detection pattern: `if isinstance(self.backend, SqliteBackend):` enables selecting appropriate SQL dialect.
  - SQLite's `julianday()` returns fractional days. Multiply by 1440 (minutes/day) for minute-level precision: `ABS((julianday(date) - julianday(:price_date)) * 1440)`.
  - SQLite requires `CAST(strftime('%Y', date) AS INTEGER)` for numeric date parts, plain `strftime()` returns strings.
  - The fuzzy matching algorithm: filter to same calendar day (year/month/day match), then ORDER BY absolute minute difference, LIMIT 1.
  - All 10 PriceLookup tests pass, mypy --strict passes, all 53 total tests pass.
  - Query class pattern with dependency injection (accept backend in constructor) enables easy testing with in-memory databases.
  - PostgreSQL parameters need CAST(:price_date AS TIMESTAMP) for date functions when passing ISO strings.
